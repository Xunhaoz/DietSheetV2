## Implementation status

The backend is a minimal slice: `POST /api/v1/meals` stores an uploaded photo and its meal record. Deliberate differences from the design, to revisit as features land:

| Area | Design | Current implementation |
| --- | --- | --- |
| Authentication | Sessions with CSRF for the website | One static Bearer token (`API_TOKEN`) mapped to one configured owner (`OWNER_ID`); no `app_user` table |
| Upload response | `202` with meal and job URLs | `201` with the meal (`200` on replay); no background jobs yet |
| Error body | `{code, message, fields?, requestId}` | FastAPI's `{"detail": ...}` |
| Image variants | `display` and `thumb` generated by workers | Only `source` is stored; `media` is `{}` until workers exist |
| Edge | Caddy terminates HTTPS | Uvicorn is exposed directly on port 8000 |
